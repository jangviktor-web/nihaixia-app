## 三、跨库链接（断链）检查

链接是**运行时注入**的：`_injectLinks` 用仓库名称把正文里的方剂/药材/穴位名包成 `formula://`、`herb://`、`acupoint://`，点击后由各仓库按名解析。

### 3.1 简体模式：无断链 ✅

| 类别 | 注入候选来源 | 点击解析 | 校验结果 |
|---|---|---|---|
| 方剂 | `FormulaRepository.getAll().name` | `getByName`（精确→模糊） | ✅ |
| 药材正名 | `HerbRepository.getAll().name` | `getExactByName`（精确） | ✅ |
| 药材别名 | `_canonicalOf` 键集（135 条） | `getExactByName`→别名归一到正名 | ✅ **135 条别名，正名缺失 0** |
| 穴位 | `allNames` + `kShortNameLinkForm` | `findByName`（精确→去「穴」） | ✅ **1 条短名映射，失败 0** |

结论：**简体模式下不存在「点了没反应」的链接。**

## 四、简繁切换的三个问题

### C1（严重）繁→简映射表只有 497 条，大量简体字的繁体形式不在表内

`trMarkdown` 转换流程：正文 S2T 转繁 → 用 `toSimplified`（**497 条手工表**）把 href 还原成简体。

问题：S2T 用的是 **OpenCC 全量字典**（原生插件），但还原用的是 497 条手工表 —— **两个方向的覆盖度不对等**。

| 华 | 華 | ❌ 缺 |

**两处失效**：
1. **点击断链**：`herb://泽兰` → S2T → `herb://澤蘭` → `toSimplified` 不还原（蘭 缺） → `getExactByName('澤蘭')` 返回 null → **点了没反应**
2. **搜索失效**：繁体用户输入「澤蘭」→ `toSimplified` 得到「泽蘭」→ 索引是「泽兰」 → **搜不到**

### C2（设计脆弱）href 往返依赖映射表本身

现在的做法是「整段 md 转繁体，再把 href 用映射表转回来」。只要映射表缺任一字，该链接就断。

**根治方向**：转换前把 href 换成 ASCII 占位符，转换后原样还原 —— **完全不依赖繁简表**，任何字都不会断。约 15 行改动。

### C3（一致性）只有 3 处接入繁体转换

| 已接入 | 未接入 |
|---|---|
| 条文卡正文（`markdown_doc_screen`） | 阅读库**列表名**（`classic_library_screen`） |
| 方剂详情内容（`formula_detail_screen`） | **搜索结果**标题/摘要（`search_tab`） |
| 药材详情内容（`herb_detail_screen`） | **穴位详情**（`acupoint_detail_screen`） |
| | **医案详情**（`medical_case_detail_screen`） |

→ 繁体模式下：点进条文是繁体，返回到列表名字变简体；搜索结果是简体；穴位/医案详情整页简体。

`traditional_display.dart` 的注释说明「只转内容文本，不转界面骨架」是有意为之，但**穴位详情、医案详情属于内容，不是骨架**，属于漏接。

### 附：现有测试覆盖不足

`test/traditional_search_test.dart` 只验了「當歸/麻黃湯/當歸」——这三个字的繁体**都在表内**，所以测试通过但掩盖了 C1。

## 五、修复记录（2026-11-05 已执行 P0 + P1）

### P0 繁体模式断链 —— 已根治
`trMarkdown` 改为**转换前把 href 换成 ASCII 占位符（`__PH0__`），转换后原样还原**，彻底不依赖繁→简映射表。表再缺字也不会断链。

### P1 繁体搜索 —— 已根治（发现比预估严重得多）
审计中进一步发现：**原手工表连「傷」都没有**（`toSimplified('傷寒')` 原样返回），即繁体用户搜「傷寒」这个核心词永远搜不到。手工枚举无法补完，改为：

1. `normalizeQuery()`：检索查询词优先走原生 OpenCC `T2S()`（覆盖全量繁体字），插件不可用时退回字符表。`ClassicSearchService.search` / `matchAssets` 已切换。
2. **映射表由 OpenCC t2s 全量生成**：522 → **3786 条**（`tool/gen_chinese_convert.py`，手工条目优先去重，只收单字→单字以保证长度不变）。同步路径（方剂/药材/医案检索）随之补全。

### 仍需真机确认（单元测试覆盖不到）
- 插件是**原生 OpenCC**，flutter_test 里 `ChineseConverter.convert` 走 catch 分支 → 繁简**转换效果**只能在真机验。

### 已关闭（P2，2026-11-05 决策）
按 `lib/data/traditional_display.dart` 的设计，繁体开关只转**内容文本**（Markdown 正文），不转界面骨架文案；阅读库列表名、页面标题、搜索结果标题、来源标签均属导航/固定文案，简体可读且点进正文已是繁体。不新增异步预转与 i18n 层，YAGNI。
