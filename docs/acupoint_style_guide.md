# 穴位详情页写法工作流（acupoints.json 数据规范）

> 适用对象：`assets/data/acupoints.json`（402 穴）的生成、审计、修复与部署。
> 配套校验：`python tool/audit_acupoints.py`（检查项 id 与本文档章节对应）。
> 讲稿原文依据：`assets/zhenjiu_lecture/`（任脉=21 号文件，其余经脉对应文件）。

## 1. 字段定义与写法标准

| 字段 | 写法标准 | 好样本 | 允许变体 |
|---|---|---|---|
| `name` | 「X 穴」全称 | 巨阙穴 | 经外奇穴可无「穴」字（三毛） |
| `meridian` | 经脉全称 | 任脉 | 经外奇穴 |
| `attribute` | 特定属性（募穴/络穴等），无则留空 | 中脘=胃之募 | 空（236 条，合法） |
| `description` | 讲稿定位原话，一段 | 巨阙=「从这个心蔽骨，两个正中间的地方，叫巨阙…」 | 空（7 条，合法） |
| `location` | **标准取法格式**：部位+骨度分寸（脐上/下 X 寸 / 横平 / 正中线），或古籍书证 | 上脘=「上腹部，前正中线上，脐中上5寸」；巨阙=「鸠尾下一寸…脐上六寸」 | 手/头面穴用解剖描述（「食指桡侧，第2掌指关节后方凹陷处」合法）；⛔ **不得填讲稿正文切片或治症口语段**（如大陵曾填「就是后跟，这是膝盖…」，审计 A8） |
| `needling` | **古籍书证优先**：《铜人》《素注》针分寸+呼吸数；无书证用讲稿针法 | 巨阙=「《铜人》针六分，留七呼，得气即泻」 | 经外奇穴无书证（「一般不针，以灸法为主」合法） |
| `moxibustion` | 灸壮格式（灸 X 壮/禁灸/不灸）或讲稿灸法段原话 | 大椎=灸法段 | 艾条灸时长（「艾条灸10-15分钟」合法） |
| `clinicalNotes` | 讲稿临床讲解（可含小节标题行），一穴一段 | 关元（小肠募/急救）、巨阙 | 允许含讲稿小节标题行（`（2-01:37:43）`式） |
| `contraindication` | 禁忌：禁灸/禁针/深刺限制/孕妇，无则留空 | 禾髎 | 空（277 条，讲稿未提即空，合法） |

## 2. 禁止项（error 级，审计 A2/A3）

1. **目录页码行**：`XXX（n-HH:MM:SS）····<页码>` 形态混入任何字段。
2. **截断混入**：`clinicalNotes` 末尾 40 字内出现下一章小节标题或「六、足阳明胃经」类章头。
3. **字段错位（张冠李戴）**：字段内容属于其他穴位（判据：内容中心穴位 ≠ 本穴名）。
   历史案例：巨阙 `moxibustion` 误填上脘段梅花灸；上脘 `needling` 误填巨阙书证。
4. **2000 字截断**：`clinicalNotes` ≥ 2000 字为生成期截断，须对照讲稿补全后消除。

## 3. 修复工作流

1. **审计**：`python tool/audit_acupoints.py` → 按 error/warning 清单定位。
2. **取材**：只从 `assets/zhenjiu_lecture/` 对应经脉文件取原文（如任脉=21 号文件），grep 穴名定位段落；禁止凭记忆改写。
3. **修改方式**：**文本级行替换**（定位 `"name": "X穴"` 行 → 40 行窗口内替换字段行，保留缩进与尾逗号）。⛔ 禁止 `json.dump` 全量重写——会把 compact 数组展开，污染 diff（+180 行假变更）。
4. **校验**：`json.load` 合法 + `total=402` + 内容断言（新文本进、旧文本出）。
5. **测试**：跑穴位相关 10 个测试文件（acupoint_*/acupuncture_erxue/llm_acu_accuracy/…）。
6. **部署**：`acupoints.json` 是打进包的资产——网页版重建部署 `docs/web`；APK 需重新构建发版。

## 4. 排版细则

- 字段值内换行用 `\n`（JSON 转义），单行长文本不折行。
- 中文标点全角；书证号《》完整；分寸用汉字（六寸）与阿拉伯（6寸）并存时以讲稿为准，不强制统一。
- `clinicalNotes` 内的讲稿小节标题行（含时间戳）**允许保留**——它们是讲稿内容的章节结构。

### 4.1 【要点归纳】段（**标准做法**，带触发阈值）

- 🔴 **触发阈值**：`clinicalNotes` 讲稿原文长度 **≥ 2500 字**（影响手机端阅读使用）时，才在末尾追加 `\n\n【要点归纳】\n` + 书面要点段；低于阈值不加，保持讲稿原样。已按用户点名完成的条目不受阈值追溯。
- 归纳段写法：口语 → 书面、长文 → 要点（建议 ≤300 字），**医学含义零增删**；要点式（①②③）优先于叙述式。
- 归纳段是润色文本，**不参与逐句溯源**；其前的讲稿原文部分溯源要求不变。
- 🔴 写入实现禁止在源码里写字面 `\n` 或 `'\\'`——工具参数经 JSON→bash→python 多层转义会变形（真实换行会切断 JSON 行）。**换行转义一律用 `json.dumps(chr(10)+...)` 生成**，反斜杠断言用 `chr(92)`。
- 审计对应：A7——原文 ≥2500 且无【要点归纳】段 → warning（提示补归纳）；已有【要点归纳】→ 校验其位于文本末尾。
