# 伤寒论卡片排版格式规范

> 适用：`assets/shanghan/clause_001.md`–`clause_390.md`（390 张条文卡）＋ `appendix_001..004`（4 张附录卡）
> 校验：`python tool/lint_shanghan_format.py`（报告）／`--gate`（门禁，error 即退出码 1）
> 更新：2026-11-06（切换 `shanghan_unified` 后重定基线）

## 一、为什么要有这份规范

模块最初由讲稿逐条拆分生成，历次修补中反复出现同类缺陷：标题/原文被硬换行截断、
同一原文重复、并卡的第二节插到第一节讲解前、原文写成裸文本行、原文块混进讲解、
序号用拉丁字母 O 冒充「〇」……每次都是**事后逐个人肉发现**。

本规范把「什么算合规」写成可执行检查，新增或修改卡片后跑一次即可判定。

## 二、卡级结构

### 2.1 文件骨架

```
#### 中文序号、原文

> 原文

**倪海厦解读**：

（讲解 / `- ` 列表 / `#####` 子标题 / 方剂行）
```

- 首行必须是 `#### 标题`
- 一个文件 = 一个阅读库条目（对应 `kShangHanLectures` 里的一条）
- **文件名即宋本条号**：`clause_176.md` = 宋本第 176 条；宋本 391–398 见金匮模块
- 清单由 `tool/rebuild_shanghan_lecture_index.py --apply` 从资产生成，**不要手改** `kShangHanLectures`
- name 前缀统一为「宋本N·」，保证阿拉伯数字条号在阅读库列表里可搜

### 2.2 标题族（切换后统一为 2 族）

| 族 | 式样 | 数量 | 适用 |
|---|---|---|---|
| **条文卡** | `中文序号、原文`（如「一七六、「伤寒」脉浮滑…」） | 390 | 宋本 1–390，一卡一条 |
| **附录卡** | `附录N：主题` | 4 | 六经总结，`appendix_001..004` |

> 2026-11-06 起旧版 5 族（`条文N：`／`条文N（中文序号）`／`中文序号：原文`／补缺卡／篇首总结）**全部废弃**，
> 统一为「中文序号、原文」式。代价：讲稿条号不再逐卡保留（旧版 264 张卡带「条文N」，
> 新版仅剩 3 处讲解性残留）；检索统一走「宋本N」/ 方名，不再设单卡孤例对照注。
> 附录卡是总结性材料，**不套条文卡的 I2–I11 规则**，lint 只扫 `clause_*.md`。

### 2.3 并卡（一文件多节）

历史资产里存在一文件多节的「并卡」，顺序必须为「第 N 条全部内容 → 第 N+1 条全部内容」，**不得把第二节的标题+原文插到第一节讲解之前**（旧缺陷见 `clause_301`/`clause_344`）。
`shanghan_unified` 已把 21 个多条合讲文件拆成「一条一文件」，当前伤寒模块不再有并卡；本节规则保留给金匮模块与历史审计。

## 三、节级结构

### 3.1 条文类小节（必须）

```
#### <标题>

> <原文>

<方剂行，如有>

<讲解>
```

1. **标题后必须紧跟原文块**（`>` 行）。中间不得插入讲解。
2. **原文块 = 本节第一个 `>` 行**。其余 `>` 行视为讲解段落，不受原文规则约束。
3. 方剂写法：原文块之后的普通段落，形如 `XX汤方：<药味>。<煎服法>`（不另加 `####`）。
4. 讲解：`**倪海厦解读**：` + 要点，或散文段落。

### 3.2 非条文类小节（豁免）

以下小节**不需要**原文块：

- 方剂小节（标题含「方」，如 `桂枝汤方（群方之祖）`）
- 篇首/主题小节（`太阳 = 表（经络 + 八纲）`、`浮脉原理`）
- 总结卡（`六经辨证总结` 等）
- 方剂汇总卡（`clause_255`，10 个方剂小节）

## 四、原文块内容规范

原文块应**只含仲景原文**，且：

| 项 | 规则 |
|---|---|
| **引号** | 方名/药名/病名用「」，不用《》或【】 |
| **序号** | 中文序号用「〇」（U+3007），不用阿拉伯 `0`、不用拉丁字母 `O`、不含空格 |
| **标点** | 全角。禁止半角 `, ( ) : ; ? !` 与方头括号 `【】` |
| **字形** | 简体。白名单除外：`塚`（大塚敬节）、`憹`（懊憹，通行排印本用字） |
| **不得混入讲解** | 出现「诸位／老师／这个／就是／呢，／啊，／里面／时候」等口语即判违规 |
| **不得重复** | 同一张卡内同一段原文只出现一次 |

### 4.1 原文与标题的一致性

- **H4 式**：`#### 中文序号：原文` 中「序号后正文」必须与原文块**逐字一致**
- **H3 式**：`条文N（中文序号）` 的阿拉伯数字与中文序号必须一致（`条文191（一百九十一）`）

## 五、反模式清单（禁止）

| 反模式 | 说明 | 曾经出现 |
|---|---|---|
| **裸行原文** | 条文写成普通文本行，不在 `>` 块内，与讲解混排 | `clause_375`（整篇霍乱篇 10 条）、`clause_211`、`clause_219` |
| **原文块混讲解** | `>` 块内既有原文又有讲解 | `clause_096`、`clause_347`、`clause_361` 等 14 张 |
| **孤儿碎行** | 截断修复后残留的半句 | `clause_143`（「胸汤」主之。」）、`clause_152` |
| **重复块** | 同一原文出现两次 | `clause_279`（旧）、`clause_219` |
| **并卡错位** | 第二节标题插到第一节讲解前 | `clause_301`、`clause_344` |
| **序号混写** | `二0 二`、`三OO` | `clause_191`、`clause_279`（旧） |
| **标题/原文截断** | 原稿固定宽度硬换行未合并 | 2026-11-05 修复 122 处续行 + 52 处标题 |

## 六、校验与门禁

```bash
python tool/lint_shanghan_format.py            # 报告（可读明细）
python tool/lint_shanghan_format.py --quiet    # 只要汇总
python tool/lint_shanghan_format.py --gate     # 门禁：有 error 退出码 1
python tool/lint_shanghan_format.py --only 375 # 只查某张
```

**规则编号**

| 规则 | 级别 | 内容 |
|---|---|---|
| I1 | error | 首行必须是 `#### 标题` |
| I2 | error | 条文类小节后必须有原文块 |
| I3 | error | 原文块混入口语 |
| I4 | error | 原文块标点不规范（半角/【】） |
| I5 | error | 中文序号混写（阿拉伯/拉丁 O/空格） |
| I6 | warn | 残留繁体字 |
| I7 | error | 裸行条文 |
| I8 | error | 同卡重复原文块 |
| I9 | error | 标题序号后的正文与原文块不一致 |
| I10 | warn | 双号式条文号与中文序号不一致 |
| I11 | error | 孤儿残片（裸行只剩序号字符，如「二0」「三0」） |

**发版前必跑** `--gate`；内容改动后必须重跑 `python tool/build_classic_search_index.py`。

## 八、修改流程

1. 改内容 → 跑 `lint --only <卡名>` 确认合规
2. 增删卡片 → 跑 `python tool/rebuild_shanghan_lecture_index.py --apply` 重建清单（勿手改）
3. 跑 `python tool/build_classic_search_index.py` 重建索引
4. 跑 `python tool/audit_verse_struct.py` / `audit_verse_punct.py` / `audit_search_coverage.py` 确认无回归
5. 跑 `flutter test test/classic_lecture_assets_test.dart test/classic_search_test.dart test/traditional_search_test.dart`
6. 跑 `dart analyze lib/`，发版前 `lint --gate` 必须为 exit 0
