## 四、接入方式（关键约束）

### 4.1 现有架构
- 卡片清单**硬编码**在 `lib/data/classic_lecture_data.dart` 的 `kShangHanLectures`，格式：
  `ClassicLecture(seq: N, name: '太阳·…', asset: 'assets/shanghan/clause_NNN.md')`
- `seq` 仅作字段，**无排序依赖**（全局 `.seq` 排序只用于 medical_case，不用于讲稿）。
- `test/classic_lecture_assets_test.dart` 断言 **`kShangHanLectures.length == 384`**，且每个 asset 非空、**首行以 `#` 开头**。

### 4.2 命名方案（不改 384 个旧文件）
新卡用**字母后缀**，物理名不进主序列，避免全量重命名：
```
assets/shanghan/clause_019a.md   # 宋本20，插在 clause_019 之后
assets/shanghan/clause_026a.md   # 宋本23
...
assets/shanghan/clause_382a.md   # 差后劳复篇（放末尾总结卡之前）
```
理由：384 个文件若按序号插入需全部重命名 + 全量改清单，diff 巨大且易错；后缀法只需新增文件 + 在清单对应位置插一条 entry。

### 4.3 标题编号：用「宋本X」，**不要用 `条文N`**
三套编号互不相同，实测：

| 对象 | 宋本20 的编号 |
|---|---|
| 宋本 | **20** |
| 倪师讲稿 | **二四** |
| App 现有 `条文N` | 20 已被占用（`clause_019` = 宋本16） |

若新卡写 `条文24`（讲稿号）会与 App 现有 `条文24` 冲突。**新卡统一用 `#### 宋本20：…`**，卡内可注「讲稿第24条」。

### 4.4 卡片模板

**A. 有讲解（10 条）**
```markdown
#### 宋本20：太阳病发汗遂漏不止（桂枝加附子汤）

> 「太阳病」，发汗，遂漏不止，其人恶风，小便难，四肢微急，难以屈伸者，「桂枝加附子汤」主之。

**倪海厦解读**（讲稿第24条，`人纪-伤寒论` L405）：
- （节选讲稿讲解，保留原意，整理为要点）
```
- 方剂行（如 23/117 条）按现有格式单列：`桂枝麻黄各半汤方…` 或 `#### 方名方` 块。
- 讲稿讲解需**整理**（口语转书面），不要原文照搬流水句。参见现有卡 `**倪海厦解读**：` 风格。

**B. 无讲解（6 条）**
```markdown
#### 宋本392：阴阳易（烧裈散）

> 「伤寒」阴阳易之为病，其人身体重，少气，少腹里急，或引阴中拘挛，热上冲胸，头重不欲举，眼中生花，膝胫拘急者，「烧裈散」主之。

> **补录说明**：本条倪师《人纪·伤寒论》讲稿未收录（差后劳复篇整篇未讲），原文依宋本补入，无讲解。
```

### 4.5 接入清单（每张新卡 3 步）
1. 新建 `assets/shanghan/clause_XXXa.md`（首行 `####`，见上模板）。
2. 在 `kShangHanLectures` **对应位置**插入 `ClassicLecture(seq: …, name: '…', asset: 'assets/shanghan/clause_XXXa.md')`，并将后续 `seq` +1（机械重编号）。
3. `test/classic_lecture_assets_test.dart` 的 `expect(kShangHanLectures.length, 384)` → 改为 `384 + N`。

### 4.6 质检（每次补完必跑）
```bash

python tool/audit_verse_struct.py                  # 结构 0/0/0
```
